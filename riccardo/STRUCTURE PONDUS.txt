::BEGINNING TO STUCTURE THE ARCHITECTURE::
--	UNDERSTANDING OF PLACEMENT OF APP STOCKS AND COMPONENTS
--	MESURE RESOURCES IN A SIGNIFICANT WINDOW
--	COMPLIANCE CHECK WITH LICENCES ::SOFTWARE ASSURANCE // WINDOWS SERVER LICENCE::
--	IN ORDER TO HAVE A CLEAN AND ORGANISED MIGRATION WE MUST START FROM THE MOST FUNDAMENTAL PARTS OF THE APPLICATION
	OR THE ONES THAT ARE IMMEDIATLY NECESSARY (AUTHENTICATION, STORAGE, ORGANIZATION OF SCHEDULED JOBS)

:ELEMENTS OF THE ARCHITECTURE:
--	WEB
	SMALL OR MEDIUM EC2 INSTANCES (RUNNING IIS(WEB SERVER MICROSOFT) W AUTO SCALING) BEHIND A LOAD BALANCER
--	DATABASE
	AMAZON RDS FOR SQL (BACKUPS AND PATCHING)(LOW EFFORT)
	IF LICENCES BLOCK RDS RUN SQL SERVER ON ONE OF THE EC2S(HIGHER OPS/COST)
--	STORAGE
	EBS GP3 VOLUMES (PHISICAL DISKS DIMENSIONED BY THE TRAFFIC) // THROUGHTPU/IOPS FOR EC2
	RDS TAKES STORAGE IF USED
--	NETWORK
	SINGLE VPC CONNECTED TO PUBLIC SUBNET FOR LOAD BALANCER 
	PRIVATE SUBNET FOR APP && DATABASE
	USE SSM TO REDUCE NATA GATEWAY COSTS // UPDATES BEHIND A BASTION
--	AUTHENTICATION AND KEYS
	AWS SECRET MANAGER --> DATABASE
	AMAZON CERTIFICATE MANAGER --> TLS CERTIFICATES (ALB) 
--	BACKUP 
	RDS AUTOMATED SNAPSHOTS // SQL SERVER BACKUPS TO S3
	CROSS REGION SNAPSHOTS (BONDED TO ISO 27001)

:COST REDUCTION:
--	RDS x meno lavoro operativo: 
	AWS gestisce il database al posto tuo, quindi fai meno manutenzione, patching e gestione infrastrutturale.
--	Opzioni di sconto a lungo termine: 
	per RDS puoi valutare piani dedicati al database, mentre per EC2 puoi usare piani di risparmio per 
	abbassare il costo se sai che le istanze resteranno attive a lungo.
--	Ridimensionamento delle istanze: 
	non usare macchine troppo grandi se il carico reale è basso; meglio partire piccoli e 
	crescere solo quando serve.
--	Usa istanze burstable o Graviton quando possibile: 
	sono spesso più economiche, ma dipende dal tipo di applicazione.
--	Per Windows e SQL Server c’è un vincolo: 
	se usi applicazioni .NET su Windows, in genere devi restare su EC2 Windows x86; 
	se invece porti l’app su .NET Core e Linux, puoi avere più scelta e spesso costi più bassi.
--	Gestione remota con strumenti centralizzati: 
	usare sessioni amministrative gestite evita di esporre RDP su Internet e può ridurre anche 
	costi accessori come IP pubblici o gateway NAT.
